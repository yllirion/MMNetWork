# MetalMadness — сетевая версия (минимальная)

Пошаговая гекс-игра про мехов: ядро правил, Canvas-клиент и сервер на Socket.IO для двух игроков.

## Запуск
```
npm install
npm start            # http://localhost:3000/   (PORT=8080 HOST=0.0.0.0 npm start — другой порт / адрес)
npm test             # ядро + сетевой тест (tests/net.test.js)
npm run build        # dist/metalmadness.html — один файл, hot-seat без сервера
```
Открой адрес сервера — в строке появится `?room=xxxxxx`. Отправь эту ссылку сопернику (кнопка «🔗 Ссылка»).
Первый вошедший — игрок 1, второй — игрок 2, остальные — наблюдатели. Для проверки в одиночку открой ссылку во второй вкладке.
`?local` в адресе — старый режим hot-seat на одном экране.

## Как устроена сеть
- **Сервер** (`server.js`) — единственный владелец состояния. На комнату один `Game` из `core/game.js`.
- **Протокол**: клиент шлёт `action` (то же самое, что раньше уходило в `apply`), сервер подставляет `player` по месту соединения,
  прогоняет через `apply` и рассылает всем `update { type, by, events, state, undo, players }`. Ещё есть `join`, `undo`, `newGame`, `presence`.
  Новое действие в ядре не требует новых сообщений.
- **Кубы** бросает только сервер. Клиентам состояние уходит через `publicState`: без `seed` / `rngState` и без порядка карт в колоде навыков
  (виден только её размер). Поэтому холостой прогон `apply` на клиенте (подсветка ходов) не позволяет подсмотреть броски и будущие карты.
  Остальное открыто обоим: мины, пилоты в руке, трек навыков, сброс.
- **Отмена** — на сервере, по тому же правилу: до первого действия с кубами; отменять может только тот, чей ход.
- **Клиент** (`client/net.js` + `client/main.js`): `who()` — это своё место; `send()` отправляет действие на сервер;
  `applied()` обрабатывает события (лог, окно выстрела) одинаково для своих и чужих действий. В чужой ход панель заблокирована.
- **Переподключение**: место привязано к токену во вкладке (`sessionStorage`); после перезагрузки страницы или обрыва связи
  сервер заново отдаёт состояние и лог боя.
- Сценарий (карта + тестовые сборки) — `client/scenario.js`, общий для сервера и hot-seat.

## Чего пока нет
Лобби и списка комнат, выбора сборок / ангара, расстановки, чата, таймеров, сохранения партий на диск (перезапуск сервера обнуляет комнаты).
Если игрок ушёл, его место может занять новый вошедший по ссылке — пароля на комнату нет.

# Ядро правил (core)

Чистый JS, без зависимостей, ES-модули, Node 18+. `npm test`.

## Идея
`apply(state, action) → { ok, state, events, usedRng } | { ok:false, error }`
- состояние — обычный JSON (можно слать по сети / сохранять);
- RNG — seeded, его состояние лежит в `state.rngState` → любая партия воспроизводима из seed + лога действий;
- `apply` ничего не мутирует; сервер (Socket.IO) и клиент (подсветка, предпросмотр) используют один и тот же код;
- `Game` — тонкая обёртка с undo: откат возможен до первого действия, использовавшего кубы.

## Структура
```
core/rules.js     флаги спорных мест правил (всё, что в доке неоднозначно, — здесь)
core/hex.js       axial-гексы point-top, линия (два варианта → в пользу защитника), арка 120°
core/data/        кубы, классы, местность, оружие (таблицы, правятся без кода)
core/state.js     карта 17×17 (odd-r offset → axial), мех, evade
core/round.js     порядок раунда: класс → кто первый → чередование → новый раунд
core/movement.js  рейтинг скорости → действия движения, стоимость шага, ограничения по классу/краю
core/los.js       линия огня, укрытия, ближайший враг (+1 ЕБ), проекция фронт/тыл
core/attack.js    бросок оружейных кубов, дальность, промах, evade, передача урона в броню
core/damage.js    броня, кубы урона, криты, уничтожение, детонация, обломки
core/heat.js      контроль нагрева в конце активации
core/engine.js    createGame + apply + обработчики действий
core/game.js      Game (undo)
```

## Действия (`action.type`)
`ACTIVATE → ROLL_PILOT → [DISCARD_DICE] → CONVERT / COMMIT_MOVE / MOVE_STEP / TURN / VIRTUAL_EVADE / JUMP / RAM / MASS_ACTIVATE / FIRE → END_ACTIVATION`,
`EMERGENCY_SHUTDOWN` (вместо броска), `RESOLVE_DECISION` (защитник: `take` | `eject` перед кубами урона).

## Принятые решения (из ответов по доку)
Крит = только крит · арка 120° · ничья по числу мехов → игрок 1 · Double остужает 2 жетона · жетоны = max(0, тепло − теплоёмкость) · таран при отрицательной разнице = 0 ·
дальность лазер/баллистика 1–9 · LRM только 6–9 · навыки пилотов, мины, ослепление — вне первой версии.

## Допущения (помечены OPEN в коде — проверь)
1. Точно на границе арки (ровно ±60°) цель считается в арке (`arcBoundaryInclusive`).
2. Всё вне фронтальной арки цели = «тыл» (2 куба брони); флангов нет.
3. Шаг: прямо — 1 действие; в передне-боковой гекс (±60°) — сначала поворот к нему (1), затем шаг (1), мех остаётся повёрнутым в сторону шага; после любого шага или прыжка — один бесплатный поворот на 60° (`turn`); назад — 3 действия без поворота; задне-боковые запрещены. Anchor: +1 к каждому из действий (поворот, шаг, virtual evade).
4. (подтверждено) Крит — только крит, повреждение не добавляет; 3 одинаковых крита = мех выведен из строя без взрыва.
5. Evade на сброшенном кубе даёт тепло (изначальный бросок), но не сохраняется на мехе.
6. Перегрев (>6 жетонов) → в следующую активацию обязательно экстренное отключение.
7. Gauss: если попал и есть помеченные грани — 1 неблокируемый урон дополнительно к обычному.
8. SRM: макс. дальность 5; активация огнемёта — `laser` (в доке не указано).
9. Тяжёлый/Средний/штурмовой «значение по выбору»/«замена» — один раз за активацию.
10. Лазер блокируется укрытием, если его размер больше класса цели.

## Клиент (Canvas, hot-seat)
- `npm start` → http://localhost:3000/?local (ES-модули напрямую)
- `npm run build` → `dist/metalmadness.html` — один файл, открывается двойным кликом
- Подсветка допустимых ходов и целей — это «холостой прогон» `apply()`: клиент не дублирует правила.
- Кубы пилотирования — картинки из `client/img/` (`<цвет>.png`, `<цвет>_e.png` = сторона с evade); при `npm run build` вшиваются в HTML.
- Замены кубов (3→1 и классовые) и корректировка огня есть в интерфейсе. Пока без UI: MASS_ACTIVATE, JUMP, RAM — ядро их умеет.

## Выстрел в два шага (корректировка огня)
`FIRE` оплачивает оружие и бросает его кубы. Если остались неиспользованные кубы пилотирования нужного цвета, выстрел ждёт:
`CORRECT {mode:'reroll', group, index, pipIds}` — переброс одного оружейного куба, `CORRECT {mode:'ignoreEvade', pipIds}` — игнор одного evade. Одна корректировка стоит те же кубы пилотирования, что и активация оружия: один куб для обычного оружия, ПАРА для Gauss (ballistic + ballistic) и PPC (laser + ballistic). CC может заменить один куб пары (`cc: id`).
затем `RESOLVE_ATTACK`. Пока выстрел не завершён, другие действия запрещены. Если корректировать нечем — выстрел разрешается сразу.

## Карта, сборки, оборудование (текущая версия)
- Карта: чётные строки — 17 гексов, нечётные — 16 (`createMap`). Поле в клиенте крупнее и по центру; над ним заготовка карточки погоды, под ним 10 слотов навыков.
- Сборки мехов: `core/data/slots.js` переводит JSON из конструктора в механику (`mechFromBuild`): класс, класс брони, скорость (кириллическая «Х» → X), своя теплоёмкость, оружие, оборудование, охладители. Тестовые сборки: `client/builds.js`.
- **MASC**: `COMMIT_MOVE {pipIds, masc:true}` — этот набор move-кубов даёт обычные действия **+1 дополнительное**, +1 тепло, раз за активацию (кнопка «получить ДД с MASC»). Обычный `COMMIT_MOVE` — без бонуса.
- **Залп**: `FIRE {targetId, weapons:[{weaponId,pipIds,useTC?}]}` — несколько орудий по одной цели; кубы хранятся по оружию (`activation.attack.shots[i].rolls`), корректировка адресуется `shot`; урон всех орудий суммируется в один бросок брони. Плазменные резаки: урон = сумма тепла на кубах.
- **Бросок пилотирования**: кубов 6 − жетоны overheat − криты охлаждения; крит управления и Compact-охладители заставляют сбросить кубы по выбору игрока. Огонь на старте активации даёт жетон (он уменьшает бросок и снимается обычным охлаждением в конце).
- **CC** (в `CORRECT {cc: id}`): любой куб превращается в куб нужного цвета только для корректировки. Свой CC бесплатен; CC союзника, который видит цель, стоит активному меху 1 тепла. Раз за активацию (ДОПУЩЕНИЕ).
- **TC**: раз за активацию либо любой куб оплачивает одно действие атаки (`FIRE {useTC:true}`), либо атакующий перебрасывает один куб урона (окно `TC_REROLL` после решения защитника).
- Оружие ближнего боя оплачивается действиями движения (`payWith:'move'`, `moveCost`): кулак 1 действие и 1 баллистический куб, меч 2 и 2, топор 3 и 3. Дистанция всегда соседний гекс, evade не превращает такой удар в промах, оружейного тепла нет. Корректировать ближний бой нельзя (ДОПУЩЕНИЕ). Anchor добавляет +1 действие к цене.
- AMS (`core/ams.js`): жёлтые баллистические кубы бросаются сразу при выстреле SRM/LRM (не корректируются); один бросок на тип ракет в залпе (все LRM вместе, все SRM вместе): свои AMS — по кубу на AMS против SRM и по два против LRM; союзные (только против LRM) — по кубу на AMS, если стоят рядом с целью или на/рядом с линией огня; куб без отметки ** / *** снимает столько суммарного урона ракет этого типа; тепла нет. Число AMS добавляется к классу меха в проверке разворота.
- Разворот цели: AC10 — 1 шаг по 60°, AC20 — 2, LRM — `floor((кубы «0» + «2 SRM») / (класс + AMS))` на каждый выстрел; шаги складываются по залпу. После брони/урона/TC атакующий выбирает (pending `TURN_TARGET`): не поворачивать, ↺/↻ до 3 шагов, 4 шага = 180° + 1 урон без брони, 5+ = 180° + 2.
- Из оборудования пока без эффекта: OS (Omni Shield); ECM работает (+1 virtual evade).

## Прыжковые двигатели
Слот `JJ-I … JJ-IV` — ОДИН прыжковый двигатель соответствующего класса (I лёгкий … IV штурмовой), а не несколько. Мех может нести несколько таких слотов.
`equipment.jumpjets` — число двигателей, `equipment.jjNames` — их названия. Прыжок (`JUMP`): куб ⇧, один двигатель, один гекс в любую сторону и поворот на 60°, 2 тепла, +1 virtual evade. Класс двигателя пока ни на что не влияет.

## Клиент: карточка меха, окно кубов, логи
- **Карточка меха** справа (наведи на мех; без наведения показывается активирующийся): название, класс, количество кубов брони, скорость, шкала теплоёмкости (8 делений: контур — ёмкость меха, заливка — тепло, набранное в текущей активации, красное — сверх ёмкости, станет жетонами overheat), HP (повреждения из прочности, череп — следующее повреждение убивает), криты, жетоны, вооружение и оборудование. Использованное в активации оружие и снаряжение (включая JJ, MASC, CC, TC) зачёркнуто и помечено «задействовано».
- **Окно кубов** по центру поля. Пока можно корректировать — интерактивное, с кнопкой `🔄 N` над каждым кубом. После выстрела — показ без перехвата мыши: кубы оружия → кубы брони → кубы урона. Закрывается само через пару секунд после конца фазы урона или при следующем действии игрока.
- В логе кубы показаны уменьшенными картинками (пилотирование, оружие, броня, урон). Картинки токенов (`tok_*`) рисуются на карте и в карточке.
- Прыжок: кнопка «Прыжок» в блоке движения включает режим выбора гекса (голубая подсветка соседних гексов).
- `client/img/`: `armor_s1..s6` — грани куба брони по порядку [0, 0, 1*, 1**, a, b]; `dmg_*` — кубы урона; `tok_*` — токены. `256_extradamage.png` пока не используется.


## Линия огня и укрытия
- Баллистика: полоса дальности считается по `дистанция + evade + virtual evade + укрытие на линии` (для ракет укрытие режет урон, см. ниже).
- LRM стреляет навесом: на линии учитываются только первый гекс после стрелка и гекс перед целью; выстрел невозможен, если первый гекс — скалы/здание/укрытие выше стрелка.
- UI: при выбранном оружии и наведении на врага вверху показываются модификаторы (`shotPreview`), на карте — траектория и подсвеченные гексы.

- **Мех на линии огня** = укрытие своего размера для цели за ним (лазер, баллистика, ракеты). Разрушаемости укрытий нет (решено: убрана).
- **CONVERT** принимает кратное число кубов (пачка): лёгкий мех меняет 3 оружейных куба на 3 move одним действием. **TC** (`kind:'tc'`): один оружейный куб → другой оружейный цвет, раз за активацию (общий флаг `tcUsed` с TC-перебросом урона и сменой типа при стрельбе).
- `activation.route` / `startFacing` — маршрут активации (рисуется линией, стартовый фейсинг — треугольник).
- **MG**: урон куба ограничен 1/2/3 при целой броне / 1 / 2 критах брони цели; для дальности virtual evade цели считается дважды. Сброшенный куб сохраняет свой evade.
- **Урон**: сначала применяется чистый урон (HP кончились — взрыв), затем ВСЕ криты (счётчик до 3, 3 крита системы = «выведен из строя»), даже после вывода из строя или уничтожения — для будущей механики ремонта.
- Броня цели: бонус местности действует и на гексах линии огня (сумма по гексам, для LRM — только по учитываемым), плюс гекс цели и +1 за ближайшего врага в арке. Баллистика/PPC: если дальность с учётом evade, virtual evade и укрытия > максимальной, выстрел невозможен.

## Обновление (здания, MASC, таран, вода)
- **Здания** можно обстреливать: `FIRE {targetHex:{q,r}, weapons}`. Урон одной атаки (залпа) ≥ 4 — здание превращается в камни или огонь (случайно). Урон не накапливается (`RULES.buildingDamageAccumulates`). Брони и окна решения нет.
- **MASC**: `USE_MASC {pipIds:[один move]}` — этот куб даёт 2 ДД, +1 тепло, раз за активацию.
- **Глубокая вода**: лазер по цели в глубокой воде теряет 2 дальности за каждый overheat цели (в обычной воде — 1), показано в подсказке прицеливания.
- **Таран**: `RAM {targetId, extraActions, via?:'jump', pipIds}` — 2 ДД (+1 anchor) или 2 jumpjet-куба (+доп.), урон = разница классов + доп., не больше класса атакующего, броня не действует, раз за активацию. Для JJ-тарана каждый куб: 2 тепла и +1 virtual evade.
- **События лога**: `overheat_token` (старт/вход в огонь), `detonation_hit.faces` (кубы ракет детонации), `building_hit`.

## Обновление (прыжок на месте, JJ и укрытия, массовая активация)
- **Прыжок на месте**: `JUMP` с `to` = своя позиция (расстояние 0): куб jumpjet, 2 тепла, +1 virtual evade, бесплатный поворот; без смены гекса (огонь не поджигает заново).
- **JJ и укрытия** (допущение): число JJ, использованных в этой активации, = радиус вокруг стрелка, в котором укрытия на линии огня игнорируются (кроме гекса цели и соседних). Затрагивает правило лазера, растяжение дальности баллистики и подсказку.
- **Массовая активация** в UI: кнопки по цветам (выбери ≥2 куба цвета) → `MASS_ACTIVATE`, дальше стрельба оплаченными орудиями без кубов.
- **Криты над мехом**: иконки `crit_<control|armor|cooling>_<1..3>.png` (положить в client/img); пока их нет — заглушка из иконки куба урона с точками уровня.

## Ввод движения на карте (`client/moveinput.js`)
Перенесён из прототипа: клик по соседнему гексу — шаг, **положение курсора в гексе выбирает бесплатный поворот** (режимы «Зоны» / «Лепестки» / «Оба», мёртвая зона в центре настраивается; выбор хранится в localStorage). Свой гекс: центр — вкл/выкл режим прыжка, край — поворот на месте. Зажатая ПКМ — режим прыжка (отпустить над гексом = прыжок, вне поля = отмена). Призрак меха, пунктирный путь, подсказка у курсора со стоимостью, зона обстрела считается от призрака. Клавиши (любая раскладка): W / Q / E / S / A / D, Space — режим прыжка, Z — отмена. После шага назад поворот запрещён и в движке (`planStep` возвращает `back`).

## Макет клиента
Сетка: угол (Новая игра / Настройки / Лог боя) · погода · подсказки · правая колонка. Правая колонка (панель активации + карточка меха) всегда равна по высоте «подсказки + карта», панели прокручиваются внутри. «Настройки» — окно над полем: режим и мёртвая зона ввода движения, описание мыши и клавиш. Лог боя по умолчанию скрыт, включается кнопкой, показывается окном над полем (состояние хранится в localStorage `mm.input`).

## Правки (evade/LRM, таран, окно выстрела)
- Evade + virtual evade вычитаются **один раз** из суммарного урона ракет типа (LRM; SRM — не вблизи) в залпе, затем AMS. Событие `evade_cut`.
- Окно выстрела всегда ждёт «Завершить выстрел» (`state.holdAttack`, клиент включает; в ядре по умолчанию выключено — тесты/боты).
- Таран с JJ: нужен хотя бы один прыжковый двигатель, число кубов ⇧ не ограничено числом двигателей.
- Подсказка дальности лазера показывает максимальную дальность по цели (с вычетом воды/огня).

## Автоматика оплаты
- «Получить ДД» берёт только полезные move-кубы (лишний не тратится). `moveCommit` в клиенте.
- Массовая активация включается в `FIRE` сама (`massPlan` в engine.js): кубов цвета меньше, чем орудий в залпе, но ≥2 → тратятся все свободные кубы цвета, +1🌡 за орудие без куба. Явный `MASS_ACTIVATE` сохранён.
- `RULES.ignoreEvadeCorrection = false` скрывает «игнор evade» в корректировке (код движка сохранён).
- JJ: здания/скалы (cliff) в радиусе прыжков стрелка не перекрывают линию огня.

## Клиент: окно выстрела и панель кубов (раунд 13.11)
- Строка «Раунд · класс · ходит» — над картой, внутри блока карты.
- «Отменить» — в строке имени меха панели пилотирования (вне активации — внизу панели). Поворот на месте только на карте (Q/E, лепестки/зоны).
- Выбранное оружие, таран, прыжок и замены сбрасываются при смене активного меха.
- Окно выстрела открывается сбоку от цели (~2 гекса, с противоположной от стрелка стороны; если не влезает — снизу/сверху, не накрывая стрелка); после ручного перетаскивания остаётся на месте до следующего выстрела.
- Выбор разворота цели (`TURN_TARGET`) — в окне выстрела, с превью поворота при наведении.
- Движок: `mustShutdown(m)` — если после броска (минус сброс за compact/control) не остаётся кубов, доступно только экстренное отключение; таран никогда не даёт переброс TC.
- Прицеливание (оружие/таран выбраны) по занятому гексу не показывает «сюда нельзя»: это цель, а не шаг. Окно выстрела закрывается при смене/окончании активации. Строка раунда наложена на верхнее поле карты.

## Новое (14.11): GA, OS, blind, пул кубов, CC
- `USE_GA {radius 1..4}`: anchor всем активным в радиусе (включая источник и врагов), источнику overheat = радиус (сразу жетонами; `RULES.gaOverheatTokens=false` → обычное тепло активации). Раз за активацию. Слот сборки `GA`.
- OS: `OS_DECISION` (`use|skip`) перед броском брони при уроне >0 (не таран/перегрев/детонация/неблокируемый), раз за вражескую активацию; +1 ЕБ и +1 overheat защитнику.
- blind: детонация даёт жетон соседним активным мехам; −2 к макс. дальности за жетон (дальность 1 не меняется, минимум 1); −1 жетон в конце собственной активации.
- Клиент: выбранные кубы пула ограничивают оружие/«Получить ДД»/MASC (`FIRE.only` для массовой активации); CC требует явно выбрать куб в пуле; лог: «активируется» раньше жетона overheat.

## Окно выстрела (единый шаблон)
Шапка со статусом («корректировка» / «ждём игрока N: …» / «завершено») → оружие (ракетная группа LRM/SRM первой: установки + одна цепочка «Σ → evade → AMS = итог» + поворот LRM; затем одиночные орудия, всё столбцом) → строка «урон по цели» → броня → кубы урона → зона решения (Завершить выстрел / OS / принять-катапульта / переброс TC кликом по кубу / разворот цели / Закрыть). Завершённые секции (оружие, броня) сворачиваются и открываются кликом. В боковой панели остаётся подсказка «ждём решения — в окне выстрела». Окно держит позицию в пределах одного выстрела. Данные: `volleyBreakdown` (attack.js).

## Огонь на линии (14.11)
Каждый гекс огня на считаемой линии даёт цели +1 virtual evade (не-лазеры) и −1 дальность лазеру. LRM считает только первый и последний гекс траектории, так что максимум +2. `stretchOf` / `validateAttack` / `shotPreview` (attack.js).
- Цель, стоящая в гексе огня, получает +1 virtual evade против не-лазеров (`los.fireTarget`); дальность лазера не меняется. На карте при прицеливании метка virtual evade рисуется на гексе цели.

## Подсказка при наведении на цель
Заголовок: `Выстрел → Дист. N · Front|Rear K · имя меха · владелец · +B[иконка брони] ([источники])`.
Источники бонуса брони: цветная плашка местности (камни в гексе цели / на линии, ×n) и иконка «ближайший враг» (цель не ближайшая в секторе). Дистанция и бонусы брони общие для всех орудий и в строках оружия не повторяются.

### Строки оружия в подсказке
Под заголовком — строка `JJ: гексы на R… игнорируются` (если были прыжки). Далее блок на группу одинакового оружия: `Имя ×N ✔ [кубы пилотирования] +тепло`; недостающие при массовой активации кубы зачёркнуты, рядом штрафное тепло. Лазер: макс. дальность и огонь на линии; баллистика: дальность, evade / virtual evade (+гекс огня), поворот цели при попадании; ракеты: вычитаемые evade+virtual evade (+огонь), AMS-кубы и поправка класса для поворота.

## Мины (`core/mines.js`)
- Слот «Миноукладчик» → `equipment.minelayer`. `PLACE_MINE {to, pipIds:[laser, missile]}`: мина на соседний свободный гекс (не огонь, не мех, не другая мина), сразу «активирована». Нагрева нет (ДОПУЩЕНИЕ).
- `state.mines {id:{owner,pos,activated}}`. Мина — объект класса L со скоростью 1; любой урон уничтожает её (по ней можно стрелять: `FIRE {targetMineId}`; свою мину и мину союзника выбрать нельзя).
- `MOVE_MINE {mineId, to, pipIds}`: любым мехом ХОЗЯИНА мины в его активацию; кубы laser / ballistic / missile (рейтинг 1: 1 куб = 1 действие, 3 куба = 2 и т.д.). Двинуть можно только мину, которая ещё НЕ активирована в этом раунде; после шага она «активирована». ДОПУЩЕНИЕ: в тексте «в начале раунда все мины → активирована» противоречит «двигаются неактивированные», поэтому принято: начало раунда сбрасывает мины в «не активирована» (замок на жетоне), «активирована» = уже ставилась/двигалась в этом раунде.
- Детонация: вражеский активный мех оказывается в гексе мины (мина вошла в его гекс ИЛИ он вошёл/запрыгнул на мину). Мина бросает 2 куба, выбирает ХОЗЯИН МИНЫ (`pending MINE_CHOICE`, `RESOLVE_DECISION {choice:'0'|'1'}`). Грани: overheat / blind / anchor жетон · 3 урона (броня работает, защитник может катапультироваться) · 1 неблокируемый · 2 поворота по 60° (поворачивает хозяин мины, как после AC). Мина после детонации исчезает.
- Через свои мины мех проходит, но закончить активацию на такой нельзя. Мина, оказавшаяся в гексе огня, сгорает без эффекта.
- Мех для красных: `Medium_Armor5_Speed1plus` (миноукладчик, большой лазер, 2× JJ-II).
- UI: кнопки «Миноукладчик» и «Двигать мины» в панели активации; жетоны мин по владельцу/состоянию; выбор куба — панель справа.

## Интерфейс v2 и экстренное отключение
- **Экстренное отключение** (`m.shutdown`, `systemsOn(m)` в `core/state.js`): от EMERGENCY_SHUTDOWN до следующей активации меха не работает всё оборудование — ECM, AMS (свои и как союзник), TC, CC (как союзник), OS; лёгкий мех теряет virtual evade класса. На следующей ACTIVATE мех включается (событие `restarted`). OS тоже отключается — (допущение: «всё оборудование»).
- **GA**: одна кнопка «Включить GA»; радиус = расстояние от меха до гекса под курсором (свой гекс = 1, максимум `RULES.gaMaxRadius`), подсветка радиуса и подсказка, клик — активация.
- **Карточка меха**: строка «класс (буква в рамке) · иконка класса брони (armor3/4/5, прочие — SVG-щит) · скорость»; оружие и оборудование в две колонки; рамка зелёная — готово/работает, красная — задействовано, жёлтая — оплачено массовой активацией, красный пунктир — отключено.
- **Раскладка**: верхняя полоса убрана, карта крупнее (по высоте окна); погода — в левом верхнем углу карты; подсказка о гексе/выстреле — полупрозрачное всплывающее окно у курсора.

## Лес, огнемёт, GA без лимита, пилоты
- **Огнемёт**: бросает 1 энергетический оружейный куб — тепло стрелку (и может поджечь лес), урона не наносит (`noDamage`); цель получает overheat как раньше.
- **GA**: радиус не ограничен (`RULES.gaMaxRadius = Infinity`).
- **Лес** (`forest`, #417332, `core/forest.js`): +1 брони как камни — в гексе цели и на линии огня. Загорается (становится огнём): за каждый энергетический оружейный куб залпа с 2 или 3 тепла — по одному гексу леса на линии, начиная от стрелка, гекс цели последним (спорная линия — вариант с большим числом леса); от огнемёта по цели в лесу; от эффекта overheat мины по меху в лесу; от взрыва меха в лесу. Броня леса считается ДО поджога (защищает от атаки, которой подожжён). Мех, под которым загорелся лес, получает +1 overheat (правило «появление огня»); мина в загоревшемся гексе сгорает. (допущения: лес на линии тоже даёт броню; лес не мешает движению и обзору)
- **Пилоты** (`core/pilots.js`): на старте у игрока столько пилотов, сколько мехов, навык 1–4 случайно. Пилот выбирается при ACTIVATE (`pilotId`; без него — первый из руки), сидит в мехе до начала следующего раунда, затем все возвращаются в руку. Бюджет покупки карт = evade броска + навык пилота, но только если evade ≥ 1 (`skillBudget`). Мех уничтожен → пилот погиб; выведен критами / пилот катапультировался → «в резерве». Если у меха в этот момент нет пилота (ещё не активировался в раунде) — судьбу принимает случайный пилот из руки владельца.
- Клиент: клик по подсвеченному меху — поверх его токена появляются карточки пилотов из руки; клик по карточке — активация (дальше кнопки бросок/отключение у токена, как раньше). Клик мимо или Esc — отмена. Имена пилотов: Yarbin, Random, Dixon, Kadmir, Ragnar, Kali, Kato, Arran, Nitt, Ano, Legrand, Javier, Mall, Jacson, Nazar, Moren, Atlas, Himera.

## Лазеры и бонус брони местности
- Лазеры — только малый, средний и большой лазер (`isLaser`).
- Любой бонус брони местности (лес, камни — в гексе цели и на линии огня, `terrainArmorOf`) не только добавляется к броне цели против всего залпа (один раз), но и уменьшает максимальную дальность каждого лазера на столько же. Бой в лесу: лазер теряет и урон, и дальность.
- Omni Shield дальность не трогает — это бонус к самому броску брони.
- Дальность считается до выстрела, по местности на линии в этот момент; лес, подожжённый этим залпом, всё равно даёт броню против него.
- Бонус «+1 брони за более близкого врага в секторе» тоже режет дальность лазеров (решено).

## GA: тепло кубами
- GA больше не даёт жетоны overheat сразу: за каждую единицу радиуса мех бросает энергетический оружейный куб (1, 1, 1, 1, 2, 3 тепла); сумма — тепло активации (`act.heat.equipment`), сравнивается с теплоёмкостью в конце активации. Радиус 4 → от 4 до 12 тепла. Флаг `RULES.gaOverheatTokens` убран.
- Крит охлаждения больше не поднимает overheat выше максимума (6).

## Жетоны overheat: максимум 6, лишнее — сразу урон
- Любой жетон overheat вне контроля тепла (огнемёт, огонь при старте активации / шаге / прыжке, появление огня под мехом, мина, OS) идёт через `addOverheat`: всё сверх 6 тут же сбрасывается — по неблокируемому кубу урона за жетон. Больше 6 жетонов на мехе не бывает. Пример: мех с 6 жетонами в лесу, огнемёт → +1 за огнемёт, +1 за загоревшийся лес → 2 куба урона.
- Флаг обязательного отключения после переполнения (`forcedShutdown`, `RULES.overheatForcesShutdown`) убран. Отключение обязательно, только когда после жетонов и критов не остаётся кубов пилотирования.

## Мелкие доработки (полировка)
- Лог: «игрок N» и имена мехов — цветом игрока.
- Подсказка при прицеливании не перекрывает линию огня (выбирает место вокруг курсора, не пересекающее отрезок стрелок → цель); в настройках — ползунок непрозрачности фона подсказки (сохраняется).
- Куб, полученный заменой, дальше менять нельзя (ядро: `CONVERT` отклоняет `origin: 'converted'`).
- Мины: кнопки «Двигать мины» больше нет — свои мины, которым хватает кубов хотя бы на один шаг, подсвечиваются при активации; у такой мины есть значок-ручка ✥ (выбранная — ✓): клик по нему выбирает / снимает выбор. Если мех не может шагнуть в гекс мины, выбирает и клик по всему гексу; если может — клик мимо значка остаётся шагом меха. Миноукладчик — кнопкой рядом с оружием.
- Подсказка замен — во всплывающем title кнопок: «(выбери кубы; можно сразу несколько)».
- Стрельба по лесу (`forest:q,r`, `targetHex`): только оружием, которое может поджечь (энергетические кубы, огнемёт), и если в гексе нет меха; выстрел только поджигает лес по обычным правилам (энерг. кубы 2–3 тепла — гексы на линии от стрелка, этот гекс последним; огнемёт — сам гекс). Стрелок греется как обычно.
- Лазеры: бонус брони «есть враг ближе в секторе» тоже режет дальность (`laserArmorCut`); открытый вопрос закрыт.

## Активация через карточки пилотов
- Клик по подсвеченному меху → компактный блок карточек пилотов на токене. Наведённая карточка увеличивается, под ней, вне блока, — маленькая красная кнопка ⏻ (экстренное отключение).
- Клик по карточке — обычная активация: пилот садится и сразу бросок пилотирования. «⏻ Отключение» — экстренное отключение с этим пилотом.
- Если бросок невозможен (перегрев), карточка неактивна и подписана «перегрев», кнопка отключения видна сразу.
- Ядро: `ACTIVATE` принимает `then: 'roll' | 'shutdown'` — одно атомарное действие (и один шаг отмены). Без `then` — как раньше (фаза ROLL, кнопки на токене; используется, когда пилотов в руке нет).

## Укрытие против ракет
- Ракетное оружие обязано отправить 1–4 урона в укрытие размера 1–4: сумма ракетного урона всего залпа (LRM + SRM вместе) уменьшается на размер укрытия на линии — один раз. Берётся наибольшее укрытие среди ракетных выстрелов залпа; у LRM считаются только его два гекса (навес), JJ-радиус стрелка укрытия игнорирует как обычно.
- Порядок: evade (по типу ракет) → AMS (по типу ракет) → укрытие (на весь залп). Событие `cover_cut`, в окне выстрела — строка «🧱 укрытие N на линии: ракеты залпа −X».
- Разрушаемости укрытий нет.

## Длинный прыжок
- `JUMP` с `jumps: N` (по умолчанию 1): N кубов ⇧ и N джетов за раз. Мех приземляется в гекс на расстоянии до N (0 — на месте); гексы между ними перелетаются (скалы, здания, мехи, мины, огонь — не важны), свободным должен быть только гекс приземления. Поворот выбирается в точке приземления: до 60° за каждый прыжок (3 прыжка — до 180°). За каждый прыжок 2 тепла и +1 virtual evade; мины срабатывают только в гексе приземления.
- Клиент: в режиме прыжка подсвечиваются все гексы, куда хватает джетов и кубов ⇧; фейсинг выбирается положением курсора в гексе приземления (как при шаге), число прыжков = max(дистанция, повороты), подсказка показывает «⇧×N, тепло».

## Слот временных дебафов на токене
- Anchor и blind делят одно место на токене (бывшее место anchor), приоритет: anchor → blind. Показывается первый из имеющихся со счётчиком; если дебафов больше одного вида — слева от него «+».
